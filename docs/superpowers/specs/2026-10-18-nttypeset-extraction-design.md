# nttypeset: extracting gloss's typesetter into `nimbleterminal.dev/nttypeset`

Status: approved 2026-10-18. Open questions for Evan are collected at the end;
questions 1 and 2 are decided (the goldmark adapter ships in the library; the
font subsets move to their own module, `nimbleterminal.dev/ntfonts`, whose
repo and vanity import exist). Question 3 was accepted with the spec on the
author's lean (the experiment takes the one-line path change). Everything else
is either taken as given from the brief or marked as the author's call.

## Intent

Gloss's `--typeset` view is a complete direct typesetter: a block and span
model, a go-text shaping engine with bounded caches, incremental layout, a
glyph-mask rasterizer, logical selection, and link and image hit areas. It
lives as unexported types on gloss's document `Loader`, mixed with Markdown
parsing, asset loading, theme lookups and animation players. This design
moves the engine into a standalone Go module, `nimbleterminal.dev/nttypeset`,
the way ntpicture, nt3d and ntqrcode were extracted, so that:

- another program can lay out and raster styled text with `go get` and no
  gloss code;
- gloss's document package shrinks to Markdown normalization, asset loading,
  viewport policy and animation composition, all of which are gloss policy;
- the engine's budgets, caches and selection model are tested on their own
  terms, independent of the `Loader`.

The design follows how Makepad splits its text stack: a pure layouter, shaper
and rasterizer behind one fonts facade; Markdown as a thin adapter streaming
blocks into one text-flow API; fonts as bytes; inline widgets as reserved
rectangles.

## Goals

- `nimbleterminal.dev/nttypeset` renders a `Document` of blocks and spans to an
  `*image.RGBA` viewport with only go-text, chroma and x/image.
- Gloss's typeset view behaves identically: every existing typeset test's
  assertions hold, and typeset exports do not change a pixel (see "Pixel
  oracle" below: gloss has no committed typeset golden today, so the plan
  makes one before the first change).
- Each phase leaves gloss's `task ci` green.
- The library enforces the engine's budgets itself and reports them as errors
  at its public boundary.

## Non-goals

- No new typesetting capability (emoji, right-to-left, hyphenation, system
  fonts). The library draws exactly what gloss draws today.
- No terminal output. nttypeset produces images; ntpicture shows them.
- No change to `experiments/typeset`, which stays a frozen comparison.
- No change to gloss's command-line flags, theme catalog, or guide text beyond
  the development notes named in the brief.

## Anti-goals

- A library that imports goldmark, ntpicture, Bubble Tea or gloss's theme
  package from its core. Any of these would make it a gloss appendage.
- A public API that exposes the display list (`[]operation`) or lets a caller
  mutate shaped runs. Those are what the caches protect.
- Panics crossing the module boundary.

## Constraints (from the brief and the repositories)

- Module paths `nimbleterminal.dev/nttypeset` and `nimbleterminal.dev/ntfonts`;
  both vanity imports are served (checked 2026-10-18: `?go-get=1` on each
  returns the `go-import` meta for `github.com/NimbleTerminal/<name>`, from
  `NimbleTerminal-infra/terraform/main.tf`). Both repos are public and empty;
  the clones at `~/projects/nttypeset` and `~/projects/ntfonts` have no
  commits. Nothing to do before the first tags.
- Dependencies limited to what the engine imports now: `github.com/go-text/typesetting`
  v0.3.5, `github.com/go-text/render` v0.2.1, `github.com/alecthomas/chroma/v2`
  v2.27.0, `golang.org/x/image` v0.47.0, and, only in the goldmark adapter
  package if it ships here, `github.com/yuin/goldmark` v1.8.2 and
  `github.com/yuin/goldmark-emoji` v1.0.5.
- Module minimum `go 1.26`; CI runs Go 1.27.2 like ntpicture. Gloss is on
  1.26.9, which satisfies it.
- Scaffold like `~/projects/ntpicture`: MIT (Neomantra Corp), README,
  AGENTS.md, DEVELOP.md, CHANGELOG.md, NOTICE.md, THIRD_PARTY_NOTICES.md
  generated by `internal/tools/notices`, CODE_OF_CONDUCT.md, Taskfile.yml with
  `GOWORK: off`, `.gitignore`, `.github/workflows/ci.yml` (ubuntu and macos,
  `task ci`). No `wasm.work` and no `examples/` module: the library has no
  browser demo and no Bubble Tea dependency. `task ci` includes a
  `GOOS=js GOARCH=wasm` build so gloss's browser build cannot break on it.
- Gloss's `task ci`, `task notices` and `task release` run with `GOWORK=off`, so
  gloss's `go.mod` must name a resolvable nttypeset version at every phase: a
  pushed pseudo-version during development, `v0.1.0` before any gloss release.
  `go.work` (ignored) adds `../nttypeset` for local iteration.
- All existing typeset tests move with the code and keep their assertions.
  White-box tests move into the library package; tests of gloss policy stay in
  gloss and use the `Loader` and the library's public accessors.

## The seam

### Stays in gloss (`internal/document`)

- Markdown parsing and normalization: `readMarkdownTree`,
  `checkMarkdownNesting`, `cleanMarkdownSource`, footnote, alert and HTML-image
  normalization, `FootnotePeer`, `ImageLayout`/`MarkdownImageLayout`.
- Asset preflight and decoding (`typeset.go`): the 2 MiB source, 32,768 node,
  32 reference, 128 MiB encoded, 16 Mi decoded-pixel budgets;
  `localMarkdownPathFrom`, `readFileFrom`, `Detect`, `decodeRaster`,
  `renderSVG`; `markdownAnimations` and the GIF/WebP players.
- Text and JSON reading and their budgets (`ReadText`, `ReadJSON`, the 2 MiB
  and formatted-text checks) in `typeset_text.go`.
- The viewport policy in `typeset_render.go`: reading measure (`typesetMeasure`,
  points to 150-DPI pixels), `TypesetViewport` with `Top/Height/Left/Zoom/End/
  Line/Link/Pixels`, export slices of 1125 pixels, the `DPI`/`MaxEdge`/`Pixels`
  scale, block anchoring across reflow, theme resolution, `Result` mapping,
  `TypesetRegion` and the ntpicture composite, the info panel fields.
- `Loader` cache fields and invalidation (`typesetHash`, `typesetBase`, …).
- `FontPreview`'s Markdown sniffing (first body line, first fenced line).
- The flag-worded font errors (`--font must be …`, `--mono must be jetbrains`)
  as thin wrappers over the library's resolver.

### Moves to the library

- The span and block model and the `Document` type.
- The glyph-mask rasterizer (`internal/typeset/raster`, unchanged, as
  `nttypeset/raster`).
- Font looks, the fallback map, the ligature-off features, face loading
  through a byte provider.
- The shaping engine and its 32 MiB shaped-run cache.
- Chroma highlighting into spans.
- The text/JSON line-block builder.
- Incremental layout (`ensure`, `block`, `starts`, `lineAt`, `table`,
  gutter numbers and chop), the display list, the per-block rollback on
  cancellation.
- The rasterizer over the display list, with palette resolution at paint time.
- Selection: `TypesetPlace`/`TypesetSelection` placement, caret math,
  highlight spans, selected text.
- Link and image rectangles.
- The font preview sample rows (the drawing, not the Markdown sniffing).
- The goldmark walk, as an adapter package: in the library as
  `nttypeset/goldmark` or in gloss. Open question 1.
- The embedded OFL font subsets, their notices, `sources.json`,
  `subsets.sha256`, and `scripts/subset-fonts.py`: to their own module,
  `nimbleterminal.dev/ntfonts`, not to nttypeset (decided; see "Fonts").

## Package layout

```
nimbleterminal.dev/nttypeset            core: Document, Engine, Layout, Palette, Selection
nimbleterminal.dev/nttypeset/raster     glyph-mask cache (moved as is)
nimbleterminal.dev/nttypeset/goldmark   goldmark AST -> Document adapter                  (open question 1)
nimbleterminal.dev/nttypeset/internal/tools/notices   THIRD_PARTY_NOTICES generator

nimbleterminal.dev/ntfonts              separate module: the 28 embedded OFL subset faces,
                                        their licenses, manifests and the subset recipe
```

The core imports go-text, chroma and x/image only. `goldmark` imports the
core, goldmark, goldmark's extension AST and goldmark-emoji. `ntfonts` imports
nothing but `embed`; it does not import nttypeset, and nttypeset does not
import ntfonts (its own tests use `golang.org/x/image/font/gofont`). The two
meet structurally: ntfonts's `Embedded` satisfies nttypeset's `FaceSource`
because that interface uses plain strings. A consumer that supplies its own
faces never downloads or links the TTFs. There is no default face source:
`NewEngine` and `Preview` without `WithFonts` return an error. (The brief's
decision 4: "gloss supplies the embedded subsets as the default provider".)

Why a separate module rather than a package: fonts change on their own axis
(coverage, a new Google Fonts pin) and should version without an nttypeset
release; other renderers can use them without a typesetter; nttypeset's repo
and module zip stay small; the OFL notices, manifests and subset script have
one home.

## Public API sketch

Names are proposals; the shapes are the design. Everything below is in package
`nttypeset` unless marked.

### Document model

```go
// Style is a set of face flags. Bold|Italic|Mono|Strike; the low three bits
// select one of the eight loaded faces, as today.
type Style uint8
const (
    Bold   Style = 1 << iota
    Italic
    Mono
    Strike
)

// Role names a semantic ink the palette resolves at paint time.
type Role uint8
const (
    RoleText   Role = iota // the palette's Foreground
    RoleAccent             // headings and links
)

type Span struct {
    Text  string
    Style Style
    Role  Role
    Ink   color.RGBA        // explicit ink; zero defers to Role and Token
    Token chroma.TokenType  // nonzero paints from Palette.Syntax
    Href  string            // link destination; not part of shaping
}

type Kind uint8
const (
    Paragraph Kind = iota
    Heading
    KindQuote  // a paragraph inside a blockquote (named for the collision with the Quote type)
    Code       // a code block: inset, code-background fill
    Line       // one line of a Lines document: no gap after it
    Rule
    KindImage  // named for the collision with the Image struct type
    Table
)

// Quote is one blockquote bar beside a block: its indent, and whether this is
// the last block of that quote (the bar stops at the content, not the gap).
type Quote struct {
    Indent int
    Last   bool
}

// Bounds are optional HTML-style limits on an image: fit without enlarging,
// align left, center or right. Zero means natural size, left.
type Bounds struct {
    Width, Height int
    Align         string
}

// Image is a reserved rectangle. Still is drawn by Raster unless Animated and
// the raster omits animated images; nil Still draws the block's Spans as a
// placeholder. Key is reported back by Layout.Images.
type Image struct {
    Key      string
    Still    image.Image
    Bounds   Bounds
    Animated bool
}

type Block struct {
    Kind   Kind
    Spans  []Span
    Rows   [][][]Span // Table: rows of cells of spans; the first row is the header
    Size   int        // font size in layout pixels; zero is 25
    Indent int        // layout pixels left of the margin
    Quotes []Quote
    Image  *Image     // Kind == Image
    Href   string     // Image: the link around it
}

// Document is what the layout consumes: blocks in reading order. Lines says
// the blocks are a file's lines, one each, which enables gutter numbers and
// chop in LayoutOptions.
type Document struct {
    Blocks []Block
    Lines  bool
}
```

Pixel neutrality: today headings and links carry the light and dark accent as
sentinel inks and the raster recognizes the pair; fills carry sentinel light
colors mapped by `typesetFill`. Both become roles (`RoleAccent`; internal fill
roles Border, Code, Header, Muted) resolved from the palette at paint time.
The resolved colors are the same, so pixels are the same, and the two
`theme.Get("light"/"dark")` sentinels leave the layout.

### Highlighting and line documents

```go
// Highlight tokenizes source with chroma. style decides bold and italic (which
// shape); each span records its Token so the palette's Syntax style colors it
// at paint time. Unknown or absent language, a lexer that changes the source,
// more than 32,768 tokens, or a cancelled ctx return one plain Mono span.
func Highlight(ctx context.Context, source, language string, style *chroma.Style) []Span

// Lines builds a Lines document: one Line block per line, tabs as four
// spaces, an empty line as one space, highlighted as a whole first so
// multi-line tokens keep their color. More than 8,192 lines is an error.
func Lines(ctx context.Context, text, language string, style *chroma.Style) (*Document, error)
```

### Fonts

```go
// Variants are plain strings so a face source need not import this package.
// (The Style flags already take the names Bold and Italic.)
const (
    VariantRegular    = "Regular"
    VariantBold       = "Bold"
    VariantItalic     = "Italic"
    VariantBoldItalic = "BoldItalic"
)
func (s Style) Variant() string // from the Bold and Italic bits

// FaceSource supplies TrueType/OpenType bytes for a family and variant. It
// uses strings only, so ntfonts (or any font package) implements it without
// importing nttypeset.
type FaceSource interface {
    Face(family, variant string) ([]byte, error)
}

// FontLook pairs a body family with a code family, by name.
type FontLook struct {
    Name, Body, Code string
}

func FontLooks() []FontLook                              // readable, editorial, technical, compact
func ResolveFont(name, override string) (FontLook, error) // "" is readable; override "" or "jetbrains"
func FontKey(name, override string) string              // name + "/" + override
```

The look table is library data: Readable = Literata/Iosevka, Editorial =
Newsreader/Iosevka, Technical = IBM Plex Sans/IBM Plex Mono, Compact = Source
Serif 4/JetBrains Mono. Fallback faces are Literata (proportional) and Iosevka
(mono), as today. The library asks its `FaceSource` for these family names;
ntfonts maps them to `GlossA…G-<Variant>.ttf`, and a source lacking a look's
family makes `SetFonts` return that error with the family name. A source that
cannot supply a fallback family (an error from `Face`) is remembered once per
style: the engine then has no fallback for that style, runes the primary face
lacks count as `Missing`, and the primary face draws its notdef glyph. Today's
panic on a failed fallback load goes away; the gofont test source and any
third-party source behave this way. Errors from
`ResolveFont` are flag-neutral (`unknown font look "x"`, `mono override must
be "jetbrains"`); gloss's `document.ResolveFont` wraps them with its flag
wording so user-visible messages do not change.

```go
// module nimbleterminal.dev/ntfonts, package ntfonts
type Source struct{}                                          // zero value is ready
func (Source) Face(family, variant string) ([]byte, error)   // "Literata", "Bold" -> GlossA-Bold.ttf
var Embedded Source
func Families() []string                                      // the seven families, sorted
func Licenses() []License                                     // for consumers' THIRD_PARTY_NOTICES
type License struct{ Family, Text string }                    // Text is the OFL as shipped
```

ntfonts is scaffolded like nttypeset (MIT, README, AGENTS.md, DEVELOP.md,
CHANGELOG.md, NOTICE.md naming the OFL fonts, THIRD_PARTY_NOTICES.md with the
seven OFL texts, Taskfile, CI). It carries gloss's `internal/document/fonts`
directory whole (the 28 subsets, seven `*.OFL.txt`, `sources.json`,
`subsets.sha256`, `README.md`, and the unused Go reference TTFs with their
`LICENSE`, so the README and manifest stay true), `scripts/subset-fonts.py`
with its root pointed at the module's font directory, and the hash and
coverage tests (`TestFontSubsetHashes`, the subset half of
`TestFontLooksAndSubsets`). Its `task ci` runs `shasum -a 256 -c subsets.sha256`.

### Palette

```go
// Palette is every color the raster uses. Syntax colors chroma tokens; nil
// paints them in Foreground.
type Palette struct {
    Background, Foreground, Muted, Border, Code, Header, Accent, Selection color.RGBA
    Syntax *chroma.Style
}
func LightPalette() Palette // gloss's light base, github syntax
func DarkPalette() Palette  // gloss's dark base, github-dark syntax
```

Gloss builds a `Palette` from `theme.Get(name)` and `styles.Get(theme.Syntax(name))`
per request. A theme change is a different palette on the same layout, so it
repaints without reshaping or relaying out, as today.

### Limits and errors

```go
// Limits bound a layout. The zero value means the defaults; a value may lower
// a limit, never raise it (ntpicture's convention).
type Limits struct {
    Blocks      int           // 32,768 per document
    Runs        int           // 32,768 style runs per block
    Runes       int           // 16,384 per paragraph
    Glyphs      int           // 262,144 per layout
    Operations  int           // 32,768 display-list entries
    Height      int           // 11,250,000 layout pixels (1125 × 10,000 pages)
    Pixels      int           // 32 Mi raster pixels
    Deadline    time.Duration // 15 s of layout time per layout, cumulative
    ShapeCache  int           // 32 MiB
    GlyphCache  int           // 32 MiB
}

var ErrLimit = errors.New("nttypeset: limit exceeded")

// A LimitError says which limit and keeps today's message text
// ("typeset layout exceeds 15 seconds", …). errors.Is(err, ErrLimit) is true.
type LimitError struct{ What string; Limit int }
```

Context errors pass through unwrapped so `errors.Is(err, context.Canceled)`
holds. Internally the engine keeps its panic-and-recover discipline (it is what
makes the per-block rollback a one-liner); every exported method recovers at
its boundary and returns an error. No panic leaves the module.

### Engine

```go
type Option func(*options)
func WithFonts(src FaceSource) Option      // required; gloss passes ntfonts.Embedded
func WithLook(name, override string) Option // default "readable", ""
func WithLimits(l Limits) Option

// Engine owns faces, the shaper, the shaped-run cache and the glyph-mask
// cache. Not safe for concurrent use: a caller serializes it, as gloss's
// Loader does with its mutex.
type Engine struct{ /* unexported */ }
func NewEngine(opts ...Option) (*Engine, error)

func (e *Engine) SetFonts(name, override string) (changed bool, err error) // clears both caches when it changes
func (e *Engine) Look() FontLook
func (e *Engine) FontKey() string
func (e *Engine) Fallbacks() []string  // fallback families used so far, sorted
func (e *Engine) Missing() []rune      // up to 32 runes with no glyph in any face, sorted
func (e *Engine) GlyphCache() raster.Stats
func (e *Engine) SetGlyphBudget(bytes int)

// Layout starts an incremental layout of doc at width layout pixels. It lays
// out nothing yet. Too many blocks is an error here.
func (e *Engine) Layout(doc *Document, width int, opts LayoutOptions) (*Layout, error)

type LayoutOptions struct {
    Numbers bool // a gutter of line numbers, Lines documents only
    Chop    bool // each line on one row, unwrapped, Lines documents only
}
```

### Layout

```go
const Margin = 50 // layout pixels around the page; the first block starts at y = Margin

type Layout struct{ /* unexported */ }

// Ensure lays out blocks until the laid height reaches bottom or the document
// ends. A cancelled ctx or a limit leaves the layout as it was before the
// block in progress, and returns the error; the next call takes it up again.
func (l *Layout) Ensure(ctx context.Context, bottom int) error
func (l *Layout) EnsureBlock(ctx context.Context, index int) error // through block index
func (l *Layout) Complete(ctx context.Context) error               // to the end, within Limits.Height

func (l *Layout) Done() bool      // every block is laid
func (l *Layout) Laid() int       // blocks laid so far
func (l *Layout) Starts() []int   // top y of each laid block
func (l *Layout) Extent() int     // laid height plus the bottom margin
func (l *Layout) ExtentX() int    // right edge of the widest text run, for panning a chopped page
func (l *Layout) Width() int
func (l *Layout) LineAt(top int) int // the line at the top of a view (Lines documents)

// Find lays out until the first run whose Href is href, or the end.
func (l *Layout) Find(ctx context.Context, href string) (image.Rectangle, bool, error)

// View is a region of the page and the raster it maps to. Scale is raster
// pixels per layout pixel (1 at 150 DPI). Pixels, if set, is the exact raster
// size, which may differ from the scaled region by a rounding pixel.
type View struct {
    Top, Left, Width, Height int
    Scale                    float64
    Pixels                   image.Point
}
func (v View) Size() image.Point                           // the raster size
func (v View) Project(r image.Rectangle) image.Rectangle   // page rectangle to raster pixels

type RasterOptions struct {
    Palette      Palette
    Selection    *Selected // highlight behind this text
    OmitAnimated bool      // leave Animated images as background for the caller to composite
}

// Raster ensures through the view's bottom and draws it. Over Limits.Pixels
// is an error.
func (l *Layout) Raster(ctx context.Context, v View, opts RasterOptions) (*image.RGBA, error)

type Link struct {
    Rect image.Rectangle // raster pixels, clipped to the view
    URL  string
}
type Placed struct {
    Rect image.Rectangle // raster pixels, unclipped
    Key  string
}
func (l *Layout) Links(v View) []Link    // text runs and images with an Href
func (l *Layout) Images(v View) []Placed // images with a Still, overlapping the view
```

`Links`, `Images` and `Raster` read the display list as laid so far; callers
`Ensure` first, as `Raster` does itself.

### Selection

```go
// Place is one end of a selection: a point on the page, or a rune of a
// paragraph of a block, which is the same place at every width and zoom.
type Place struct {
    Point             image.Point
    Block, Para, Rune int
    Placed            bool
}
type Selection struct{ Anchor, Focus Place }

// Selected is a selection resolved against a layout.
type Selected struct{ /* unexported carets and the layout */ }

// Select places both ends, laying out as far as a placed end asks. It returns
// nil, nil when a place is not in the document.
func (l *Layout) Select(ctx context.Context, s Selection) (*Selected, error)
func (s *Selected) Places() Selection // both ends placed, points kept
func (s *Selected) Text() string      // reading order; wraps rejoined, paragraphs by newline, table cells by tab, blocks by a blank line
```

Gutter numbers are never text: `Select` and `Text` skip them, as today.

### Font preview

// Preview draws one sample row per look: the look's name in bold, body in its

### goldmark adapter (package `nttypeset/goldmark`, open question 1)

```go
type Options struct {
    // Images by destination. A destination that is absent or has a nil Still
    // lays out as the placeholder "[image unavailable: dest]".
    Images map[string]nttypeset.Image
    // Bounds for an image node, from attributes the caller's normalization
    // set; nil means natural size.
    Bounds func(*ast.Image) nttypeset.Bounds
    // Syntax decides bold and italic for fenced code; nil leaves code plain.
    Syntax *chroma.Style
}

// Build walks a parsed tree into blocks. It does not parse: the caller owns
// goldmark's parser, extensions and normalization. Headings size 50…29 by
// level; lists and quotes indent 24; code blocks over 8,192 lines, more than
// 32,768 blocks, or a cancelled ctx are errors.
func Build(ctx context.Context, root ast.Node, source []byte, opts Options) (*nttypeset.Document, error)
```

The walk is today's `prepared.walk`, `inline`, `standaloneImage` and
`imageLink` with the asset lookups replaced by `Options.Images` and
`MarkdownImageLayout` by `Options.Bounds`. If the adapter stays in gloss, the
same code is `internal/document/typeset_blocks.go` and nothing in the library
changes.

### Pixel oracle

Gloss's `task ci` has no typeset pixel comparison: `TestTypesetExportCLI`
checks only that PNGs exist at the asked edge, and the browser goldens are
text screens. The brief's "golden exports must not change pixels" therefore
needs an oracle, and the plan makes one before phase 1 (author's call):

- A script under gloss's `scripts/` exports, with the gloss binary built at
  the current commit, `examples/typeset.md` (every page), a plain text file and
  a JSON file from `examples/`, at 150 DPI, for each of the four looks, light
  and dark, and the text files again with `--line-numbers` and
  `--chop-long-lines`, and writes a SHA-256 manifest of the PNG bytes.
- The manifest is generated once from the pre-extraction commit into an
  ignored directory (`dist/typeset-baseline/`) and re-checked after every
  phase. It is not committed: it would break on every go-text or x/image
  bump for reasons unrelated to gloss.
- The glyph-mask test's mask-versus-direct tolerance and the "fresh engine
  equals cached engine" assertions remain the in-repo guards.

Making the baseline a committed hash test is possible later; it is not part
of this extraction.

## Phases

Each phase ends with gloss's `task ci` green (`GOWORK=off`) and, from phase 2,
nttypeset's `task ci` green.

1. **Inside gloss: make the engine theme- and animation-free.** Replace the
   sentinel inks and fills with roles resolved from a `Palette` passed to the
   raster; move `prepared.animations` out of the layout behind an
   `OmitAnimated` raster flag and an `Animated` image flag; pass `ctx` into
   layout entry points instead of setting `engine.ctx` from the loader; give
   `FontPreview` a self-contained sample routine. No file moves, no public
   change, all tests pass as they are.
2. **Create the module with raster and the engine.** Scaffold the repository;
   move `internal/typeset/raster`; move the model, engine, layout, raster,
   selection, highlighting, `Lines` and `Preview` behind the API above; a test
   `FaceSource` on gofont. Push to `main`, pin the pseudo-version in gloss's
   `go.mod`, add `../nttypeset` to `go.work`; gloss's `document` becomes glue
   with a temporary `FaceSource` over `internal/document/fonts`. Move the
   white-box tests.
3. **Create ntfonts and move the adapters.** Scaffold `ntfonts`, move the
   font directory, script and tests, push and pin; gloss switches to
   `ntfonts.Embedded`, deletes its copy, and its notices tool and Taskfile
   `sources` follow. Move the `goldmark` adapter if open question 1 says so.
   Update DEVELOP.md's typeset section and sibling-checkout paragraph and
   AGENTS.md's layout list.
4. **Publish and pin.** ntfonts `v0.1.0`, then nttypeset `v0.1.0`, each with a
   CHANGELOG entry; gloss pins both, regenerates notices, `GOWORK=off task ci`
   and `task demo-check` pass.

Phase 0, before any of these, builds the pixel oracle above.

If a gloss release has to ship between phases 2 and 4, the pseudo-version
pin is replaced by tagging what exists as `v0.1.0` at that point, and the
remaining phases ship as `v0.2.0` with a second pin and notices regeneration.
The plan assumes one tag at the end; the contingency changes schedule, not
code.
